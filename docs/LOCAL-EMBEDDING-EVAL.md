# 本地小 embedding / reranker 替换评估

> 日期：2026-10-05 · 目标：评估把 HMEM 的远程 embedding/reranker 换成**本地小模型**
> 当前链路：HMEM → 璇玑网关(3001) → 硅基流动（远程付费 API），model = `bge-m3` / `rerankv2m3`

## 一、结论先说

| 组件 | 本地小模型 | 质量对比（P@5） | 延迟 | 结论 |
|---|---|---|---|---|
| **Embedding** | bge-small-zh-v1.5（24M） | 0.850 vs 远程 **0.900** | **1.9ms** vs 23.8ms | ✅ **可换**（质量基本持平，快 12×） |
| **Reranker** | bge-reranker-base（278M） | 0.775 vs 远程 **0.875** | 11.7ms vs 31.6ms | ⚠️ **不建议**（质量掉明显，尤其长文排序） |

**推荐**：**embedding 换本地**（纯赢），**reranker 保留远程**；若要求全本地，reranker 应换
`bge-reranker-v2-m3`（与远程同款，但更重、CPU 上慢）。

## 二、测试方法

- **语料**：真实 `dev.db` 全量 199 条记忆（非合成）。
- **标注**：按主题人工聚类出 8 个查询及其相关文档集（内容驱动，与模型无关）。
- **指标**：Precision@5、MRR；延迟为单条/单对均值（本机 8 核 CPU、torch 2.14 CPU 版）。
- **对照**：远程 = 璇玑转发的 `bge-m3` / `rerankv2m3`。

## 三、Embedding 结果

| query | local P@5 | remote P@5 | local MRR | remote MRR |
|---|---|---|---|---|
| 星语 语音 ASR 模型 | 1.00 | 1.00 | 1.000 | 1.000 |
| 掀将 暗棋 引擎 规则 | 1.00 | 1.00 | 1.000 | 1.000 |
| 玄盘 原生 移植 golden | 0.80 | 0.80 | 1.000 | 1.000 |
| profile 配置 作用域 | 1.00 | 1.00 | 1.000 | 1.000 |
| ModelScope 模型下载 | 0.80 | 0.80 | 1.000 | 1.000 |
| 上游 超时 璇玑 | 1.00 | 1.00 | 1.000 | 1.000 |
| edge-tts SSML 语音合成 | 0.60 | 0.80 | 1.000 | 1.000 |
| HMEM 上下文卸载 offload | 0.60 | 0.80 | 1.000 | 1.000 |
| **平均** | **0.850** | **0.900** | **1.000** | **1.000** |

- MRR 完全一致；P@5 差异只出现在 2 个查询，且是 199 条小库上的边际差异 → **视为基本持平**。
- 延迟：本地 **1.9ms** vs 远程 **23.8ms**（快 ~12×）；批量编码 199 条本地 9.2s / 远程 4.8s（远程走大 batch 更优）。

## 四、Reranker 结果

| query | local P@5 | remote P@5 |
|---|---|---|
| 星语 语音 ASR 模型 | 1.00 | 1.00 |
| 掀将 暗棋 引擎 规则 | 1.00 | 1.00 |
| **玄盘 原生 移植 golden** | **0.20** | **0.80** |
| profile 配置 作用域 | 0.80 | 1.00 |
| ModelScope 模型下载 | 0.80 | 0.80 |
| 上游 超时 璇玑 | 1.00 | 1.00 |
| edge-tts SSML 语音合成 | 0.60 | 0.60 |
| HMEM 上下文卸载 offload | 0.80 | 0.80 |
| **平均** | **0.775** | **0.875** |

- 本地 `bge-reranker-base` 在「玄盘 原生 移植 golden」上**显著劣化（0.80→0.20）**——该组文档长、
  术语密，base 版区分力不足。**reranker 直接决定 top-K 顺序，质量损失不可接受**。
- 保留远程，或本地换 `bge-reranker-v2-m3`（同款、568M、CPU 上更慢）需再测。

## 五、换本地的真实收益（不是省钱）

- **成本**：bge-m3 经硅基流动按 token 计费，但 HMEM 调用量小，费用可忽略——**省钱不是理由**。
- **真正价值**：①**摆脱网络依赖**——现在 embedding 走 璇玑→硅基流动，链路一断，HMEM 检索
  静默退化为纯 FTS+HRR；本地化后检索**永远可用**。②**延迟快 12×**，prefetch 更跟手。
- **代价**：多一个本地进程（ONNX Runtime，~100MB 模型 + 内存），需 supervisor 守护。

## 六、最终落地方式（已实施）

**架构定位（按用户决策修正）**：不动 HMEM 代码——HMEM 继续无脑调璇玑网关的
`bge-m3`；本地模型以**独立服务 + 璇玑备用上游**的形式接入，对 HMEM **完全透明**。

1. **本地服务**：`/data/codes/bge-m3-local`（FastAPI + ONNX Runtime，端口 8069）。
   模型 = **BAAI/bge-m3 同款**（1024 维，非小模型——小模型维度/空间不同，会破坏向量库）。
2. **注册进璇玑**：upstream `本地bge-m3`（`kind: emb`），路由
   `bge-m3 → [免费小模型, 免费小模型-lxr, 本地bge-m3]`（`primary_backup`）。
3. **主备切换已验证**：request_log 证实主上游失败时自动兜底本地（status 200）。
4. **不换小模型、不改 HMEM 检索代码**——这是关键修正：最初"换 bge-small + 改
   EmbeddingClient"的思路是错的（维度不兼容 + 侵入业务代码）。

> 详见 `/data/codes/bge-m3-local/README.md`。
