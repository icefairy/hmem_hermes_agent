# Engram → HMEM 适用性评估

> 评估日期：2026-10-04 · 对象论文：DeepSeek-AI《Conditional Memory via Scalable Lookup:
> A New Axis of Sparsity for Large Language Models》(arXiv:2601.07372, 2026-01)

## 一、Engram 是什么（一句话）

Transformer 缺"原生知识查找原语"，被迫用 Attention/FFN **计算**去模拟**检索**（如记住
"Princess of Wales"这种定型短语要烧掉好几层）。Engram = 现代化的 **N-gram 嵌入表**，
把静态知识**烤进参数**、推理时 **O(1) 确定性查表**，再与隐藏态**门控融合**。

核心组件：①分词器压缩（NFKC/小写归一，词表 -23%）②多头哈希 N-gram 检索
③上下文感知门控 αₜ（检索到的静态记忆与当前上下文冲突时压制）④Zipfian 分层存储
⑤与 MoE 的 **U 型稀疏性分配定律**（~20-25% 非激活参数给 Engram 最优）。

## 二、为什么"整体搬到 HMEM"不成立（层次错配）

| Engram 前提 | HMEM 现实 |
|---|---|
| 知识在**预训练**时烤进 embedding 表 | HMEM 是**外部服务**，无训练、无反向传播 |
| 与 MoE 分配**参数预算** | HMEM 没有 MoE，参数预算是训练期概念 |
| 检索结果与**隐藏态 hₜ** 门控融合 | HMEM 返回**文本**，不接模型内部隐藏态 |
| 把局部依赖卸载给查表、**释放 attention** | HMEM 不跑 attention，无"注意力容量"可释放 |

论文标题里的增益（BBH +5、NIAH 84→97、CMMLU +4）**全部发生在模型内部**，
是"模型变聪明了"，不是"检索库变好了"。**Engram 是模型架构，HMEM 是记忆数据库，
两者不在同一层**——这是评估的核心结论。

## 三、可迁移的思想（逐个实测/论证）

### ✅ ① 分词器压缩 / 文本归一化 —— 值得做（低风险）

Engram 归一化后词表 -23%。HMEM 实测（真实库，`content_jieba` 列）：

| 库 | 记忆数 | 内容被归一化改变 | 词表压缩 | 归一化合并的同形 token 组 |
|---|---|---|---|---|
| dev.db | 199 | 100% | 4781→4627 (**-3.2%**) | 146 例 |
| default.db | 2036 | 97.6% | 48110→47853 (**-0.5%**) | 238 例 |

合并实例：`（` vs `(`、`⑦` vs `7`、`：` vs `:`、`Math` vs `math`、`MCP` vs `mcp`。
**结论**：归一化真实有效，但收益**小**（0.5-3.2%，远低于 Engram 的 23%——因为
HMEM 的 jieba 分词已吃掉了大部分中文分词问题）。**价值在正确性**（全角/半角、
大小写不一致时 FTS 能命中），适合作为**低风险卫生改进**。

### ⚠️ ② 上下文感知门控（αₜ）—— 最有价值，中等成本

Engram 的关键洞察：检索到的静态记忆**不能无脑用**，要用当前上下文**门控**，
冲突则压制（αₜ→0）。HMEM 现状：FTS + 向量 + HRR **加权求和**（`_compute_score`），
词面命中和语义命中等权叠加——**一条词面高度重合但语义跑题的旧记忆会刷高分**。
可迁移做法：**用 HRR/向量上下文相似度给词面命中做门控**（本地 numpy，无 API），
即 `score = Σ wᵢ·simᵢ · gate(语义相似度)`。这是**真正能提升检索质量**的一条。

### 🔸 ③ N-gram 倒排索引（O(1) 短语查找）—— 可选，收益存疑

Engram 的"哈希 N-gram → 静态表"。HMEM 版：建 bi/tri-gram 倒排表，让重复长短语
（"K8s 部署手册"）秒命中、免向量+rerank。但 **jieba + FTS5 已覆盖大部分**，
除非实测证明 FTS 对短查询/长短语召回弱，否则**边际收益低**。

### ❌ ④ U 型稀疏性分配 / Zipfian 分层 —— 不适用

前者是训练期参数预算问题；后者在 2000 条规模下 SQLite 已够快。

## 四、建议（按性价比排序）

1. **做**：文本归一化（NFKC + 小写 + 全半角），作用于 `_tokenize` + 查询侧同样归一。
   低风险、可回滚（只影响新增/重建索引），修 FTS 大小写/全半角漏检。
2. **试**：词面命中的语义门控（HRR，本地无 API）。需先建小评测集验证是否真提升。
3. **暂缓**：N-gram 倒排（先测 FTS 短查询召回，有痛点再上）。
4. **不做**：整体移植 Engram（层次错配）。

> 若真想在"模型层"用 Engram：那是**换基座/微调**的事（需 DSA 训过 Engram 的模型权重），
> 与自建外部记忆库（HMEM）是两个正交方向，不能互相替代。
